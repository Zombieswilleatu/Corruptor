## Actual match timing

Both runs use one worker, normal garbage collection, one explicit warmup per
case and the same timing contract. CPython recorded three samples per case;
PyPy recorded ten. Setup, explicit decisions, all 20 hooks per round,
transactions, full semantic history and victory are included. Policy selection,
Godot, input loading, comparison snapshots/digests and export are excluded.
Every measured game's final digest is checked outside its timer. Profiling is
a separate run.

| spoils_rekindle | 17 | 19.07 s | 6.53 s | 2.92× |

This is **66.27% less wall time** across these two reference means. Reports have
the same processor description, eight logical CPUs and Windows build 10.0.26200;
their raw OS labels differ between CPython's Windows-11 and PyPy's Windows-10 and
are retained. These were successive user runs, not interleaved runtime blocks.
The earlier three-sample CPython short case varies substantially, so the observed
ratio is not a guaranteed multiplier for other games or hardware.

The shorter PyPy case ranges from 3.58 to 4.00 seconds, median 3.67. Its first
five samples average 3.84 seconds and last five 3.61, consistent with continuing
warmup, but the run does not isolate the cause. The longer case ranges from
6.44 to 6.80 seconds, median 6.51; the corresponding five-sample means are 6.55
and 6.51 seconds. All ten samples remain in the published means. One explicit
warmup does not establish steady-state JIT performance, and cold-start cost was
not separately recorded.

At the all-sample mean, simple arithmetic gives about 702 repetitions per hour
or 2.97 days for 50,000 on one worker. This refers only to the two fixed inputs;
it is not measured nine-Lord doctrine capacity. The 50 ms target remains unmet.
Memory, runtime/JIT options, worker scaling and policy selection cost remain
unmeasured.

## Next optimization

PyPy improves this path without changing rules, but full-state copying remains
the first code target. Its separate profiles place `copy_data` at 4.36 of 7.34
seconds and 7.86 of 11.06 seconds, about 59% and 71% cumulative. Transaction
`snapshot()` alone accounts for 4.24 and 7.67 profiled seconds. These instrumented
fractions must not be treated as fractions of the unprofiled match timings;
PyPy's [performance guidance](https://pypy.org/performance.html) warns about
profiler distortion.

Reduce the amount of state and unchanged history copied per transaction while
preserving shared-container identity, detached public snapshots and complete
rollback after rejected or exceptional handlers. Keep both accepted runtime
references when measuring code changes and retain exact Godot state/event parity.
PyPy is now a verified explicit runtime for this bounded path; automatic
interpreter selection is unchanged. Remaining Lords, declared powers, paid Rites
and Resummon stay outside this adapter, and no balance or UI changes follow from
this result.
