# U13 manual combat board — 2026-09-08

## Scope

`Prototype/U13/U13Board.tscn` is the first manual U13 board. It reuses
UI2's HandView (including subject art, selection and inspection), Gremory
portrait catalog and upper/lower Domain1 artwork. A separate controller binds
these surfaces to U13 player views and submissions. No U12 controller, scene,
rule source, asset or project main scene is changed.

This is still the explicit Gremory basic combat profile, not a complete U13
match. Choose Pass, Siege or Ward; select individual physical cards; queue
Predator of Ruin in either lane; reserve exactly two selected cards for
Inevitable Ruin targeting either Castle. Ruin payments disappear from the
available hand so they cannot also pay for combat. Clear powers returns them.
Every candidate passes U13Match.preview_submission (and therefore U13Legality
for powers); commit passes submit and the authoritative hook driver.

The setup remains the tested opening combat fixture: Gremory mirrors, two
plain Integrity Castles, Wright guards, four cards each and the shared Gremory
Breach. This does not implement Keep/Bastion powers, Development, Hunt, normal
round draws, economy progression or victory. Restart restores the opening
hand. Do not call this a complete playable match or use it for tuning.

## Opponent

U13BoardSession contains a scoped random-legal exercise chooser for both
implemented Gremory powers. It never reads the human submission or hand. It
uses the opponent's player view to generate candidates, and match preview to
filter them. One legal power type is chosen uniformly, then a canonical legal
payload for that power uniformly; no power pass if at least one is legal.
Sorted physical card pairs exclude payment permutations. With no legal power
it passes powers. Keys include round, player and decision/power; purpose keys
are BOT_POWER_CHOICE and BOT_POWER_TARGET. Combat uses BOT_COMBAT_CHOICE over
legal single-card/pair Siege/Ward orders; no legal candidate means combat pass.
The complete power-plus-combat plan is validated, preserving shared payment
and cooldown ownership. There is no strategic doctrine in this profile.

This starts the addendum's Gremory declaration path. Shared multi-Lord
enumeration, generalized doctrine dispatch, batch runners and frequency
instrumentation remain open. The fixed-seed manual board produces no win-rate,
balance or field-density claims. It does not replace a future real doctrine.

## Playback and exit

Every Commit & resolve runs to Marching, then animates its recorded tape,
including rounds without a clash. All suits use the same interpolator. New
committed Marchers hold in their birth round; Gremory summons move immediately.
Stats/events retain the pre-Marching view during animation; the resolved view
appears when it finishes. Skip animation completes Aftermath once. Input is
locked during playback; Restart cancels it. Rendering never feeds fractional
visual positions back into the fixed-point simulation.

The user reported Butchers jumping in the prior smoke UI. Its exact cause is
not established. New regression checks explicitly cover no-contact Butcher
midpoint/end positions and birth hold, plus scene commit/playback routing.
Godot visual confirmation on this board is still required before calling the
reported symptom resolved.

The user confirmed Alt+F4 exits without the engine cleanup messages produced by
Ctrl+C. Normal window close or the board's Exit button is the supported exit;
no simulation change was made for those interruption-only messages.

## Launch

From the U13 project folder:

```bash
bash Scripts/Sim/run_u13_board.sh "$u13_godot"
```

This skips all tests and opens the board directly. F6 on U13Board.tscn also
works; F5 continues to use the existing project main scene.

## Direct-launch repair after local 21cb55d report

The first local launch exposed absent `.godot/imported/*.ctex` files plus
reversed arguments in U13DomainRow.draw_texture_rect_region. The call now uses
Godot's documented texture, destination rectangle, source rectangle order.

U13BoardTextures decodes the source PNGs with Image.load and caches
ImageTextures, so running from a source checkout does not depend on an editor
import pass. This covers Domain1, BottomBanner, all subject faces/backs and the
Gremory portrait, not just the two assets named in the first error log. The
loader uses the existing UI2 path catalogs. U13BoardHand is a frozen copy of
UI2 HandView with only its class name and texture loading adapted, preserving
selection, fan layout, inspection and input behavior. The original UI2 sources
are unchanged. Future shared-component extraction should keep those behaviors.
This source-PNG route is for the development board; exported builds must either
include source PNG files or supply an imported-asset loading route.

The board runner checks source textures and cache reuse before the scene
checks. Static verification confirms the board's presentation dependencies no
longer preload PNG resources. Godot 4.7.2 runtime verification remains pending.

API references: [CanvasItem drawing](https://docs.godotengine.org/en/stable/classes/class_canvasitem.html#class-canvasitem-method-draw-texture-rect-region)
and [ImageTexture](https://docs.godotengine.org/en/stable/classes/class_imagetexture.html).
