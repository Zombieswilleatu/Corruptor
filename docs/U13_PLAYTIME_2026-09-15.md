# Playable match timing

The playable board records real elapsed time as presentation metadata. It does not change U13 rules, simulation snapshots, hashes, PySim fixtures or policy inputs.

## Player experience

- Header: PLAYTIME HH:MM:SS. Hover for decision/review and resolution breakdowns.
- Match result: total and both categories.
- PAUSE beside SAVE/LOAD: available between computation/playback periods. Opens a modal Resume dialog and pauses scene processing.
- Setup, explicit pause, time outside the focused game window, time closed, and time after final playback finishes do not count.
- Decision time includes Stockpile/Slaver choices, planning and board/Aftermath review. Resolution time includes foreground worker preparation/computation and animation playback. It measures actual wall time, independent of playback speed.
- Losing window focus excludes elapsed time but does not cancel or suspend a worker or ongoing playback. Use PAUSE between resolutions for a deliberate break. No inactivity heuristic guesses whether a focused player is thinking or away.
- Fresh games start at zero. Loading resumes only recorded time; loading an earlier save resumes that save's counters, not later abandoned play.
- Old saves remain usable. With no timing history, tracking starts at zero and shows an asterisk / “partial”; it never invents earlier duration. Invalid timing metadata also falls back to partial history without rejecting an otherwise valid game.

## Save representation

The existing playable JSON envelope retains its lossless `codec` and `payload`. A separate, human-readable `playtime` member contains:

```json
{"version":1,"decision_ms":120000,"resolution_ms":30000,"total_ms":150000,"history_complete":true}
```

The encoded session checkpoint inside `payload` is unchanged. Runtime monotonic clock origins and pause/focus flags are not serialized. New counters are rebased on load, so wall time between sessions is excluded. Totals must equal the category sum; values must be finite, nonnegative whole milliseconds within JSON's exact integer range. Timing is user-facing telemetry, not authoritative or tamper-proof evidence.

Implementation: `Prototype/U13/U13Playtime.gd` and the playable board adapter. The production simulation and other previews do not import this timer.

## Verification

The deterministic timer suite covers category accounting, excluded intervals, JSON round trips, time closed, partial history, malformed values and duration formatting. The playable-board suite exercises timed and legacy saves, unchanged authority/decisions, focus exclusion, modal pause/resume and setup exclusion. Existing action-flow coverage checks the shared UI.
