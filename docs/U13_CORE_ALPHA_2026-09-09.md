Runtime: **Godot 4.7.2 stable**. Local engine verification is required before
calling this checkpoint complete. This change supplies the gates and measurements;

## Run

From the U13 checkout in Git Bash, with `GODOT_U13` set to the executable:

```bash
git pull --ff-only origin u13-lord-overhaul
bash Scripts/Sim/run_u13_foundation_tests.sh "$GODOT_U13" --alpha
bash Scripts/Sim/run_u13_alpha_batch.sh "$GODOT_U13"
```

The focused gate expects **11/11**: manifest/fixture, random restored replay,
Scorch/Breath, Scorch/Rout, existing lane-aura movement, automatic construction,
existing construction rules, construction random replay, Scorch visuals, artillery impact timing, and the direct-board integration.
Each has the existing **30-second** default watchdog. Full foundation now has
**48** runners; the existing board subset still has **14**.

Default matrix: **16 ordered pairs**, including all four mirrors and both seat
orders for each distinct matchup, one seed each, six rounds plus restored replay.
Every pair/seed has a separate process and the existing batch **300-second**
watchdog. A slow or failing shard stops the wrapper; completed shards, the full
manifest, partial output, and logs remain available. No watchdog was increased.

Each run creates a unique `Downloads/u13-alpha-XXXXXX` directory. Share
`report.json` after success, or the failing numbered log and `manifest.tsv`.
The wrapper prints progress paths immediately and a reminder every 15 seconds.

To reproduce one matchup or extend sampling:

```bash
bash Scripts/Sim/run_u13_alpha_batch.sh "$GODOT_U13" --pair=Kalligan,Humbaba
bash Scripts/Sim/run_u13_alpha_batch.sh "$GODOT_U13" --trials=2 --rounds=8 --seed-prefix=u13-alpha-second
```

A subset report explicitly says `matrix_complete: false`. Replays use the same
seed and fixture; the summary counts baseline rounds only. The same seed suffix
is used across matchups to support comparisons without a sequential RNG stream.

## Fixture and replay scope

`U13AlphaScenario` uses the shared Kalligan/Humbaba/Deimos/Gremory content path.
Both seats have two operational Siege Engines at 12 Integrity, a vulnerable
Bastion at 3, and protected unbuilt Keep and Stockpile slots. Each has the existing
four-card exercise hand, two Wright Guards, and two Repair tokens. Stable Castle
instances and one shared Castle Guard zone per player remain authoritative.

These are bounded combat-slice exercises. They do not introduce normal draws,
victory, the full Veil loop, Guard deployment/Summon/Profane, other Castle printed
powers, or later Lords. Finite hands matter when interpreting later-round density.

The batch shares the original `U13RandomBatch` lifecycle and asks the existing
random-legal chooser for each plan. Both players plan before either submits.
The chooser retains centralized legality, keyed RNG, and any real-doctrine
precedence; it does not force specific powers to inflate coverage.

The baseline captures public world/event digests after every hook and a full
snapshot digest at one rotating checkpoint each round. The replay actually
replaces its match owner with a fresh, JSON-restored owner at those checkpoints
and continues from it. Six rounds cover, after execution:

1. Submission lock.
2. Post-resolution movement state (aura/Rout state).
3. Marching.
4. Persistent advancement.
5. Combat resolution.
6. Marching start (hazard pulse).

The complete deterministic trial result must match: plans, hook traces, checkpoint
digests, telemetry, and final authoritative state/events. Timing data is separate.
Checkpoint serialization/restore cost is separately measured from planning and hook
cost; these timings are CPU wall times, **not rendered frame rate**.

## Reading the report

- `matrix_complete` means all 16 pair identities are present and replay-verified.
  It is not a claim that every mechanic fired.
- `powers_by_lord` maps declarations, resolutions and fizzles to the actual Lord,
  rather than treating seat 0 as the same Lord throughout the matrix.
- `powers_without_resolution` makes missing random coverage explicit. A green
  replay with a missing power still requires the focused power gate and review.
- `summary_by_seat` contains density histograms, arrivals, waiters, construction,
  artillery, hazard and passive counters. Its seat keys span different Lords;
  consult individual trials for matchup-specific interpretation.
- Round-limit pending effects are censored observations. All-pass/unchanged-world
  counters are diagnostic observations, not automatic proof of a stall.
- No win rates, balance verdicts, or threshold tuning from means alone.

A successful local gate and matrix close this verification pass. Review any
missing coverage, fizzles or timing outliers before the full Marching audit and
then the spatial/Orias work. This does not mark the complete production loop done.

## Construction interaction amendment

`U13_CASTLE_DEVELOPMENT_V2` implements the requested persistent project:

- Select Construct and a Castle once. It receives +3 at each Development until
  another project is selected, it is commissioned, or it completes.
- A paid Construct gets the same single +3 plus its payment progress. Payments are
  never repeated automatically; passing, combat, powers or repair elsewhere leave
  the selected project running.
- Switching pauses the old Castle at its current progress. Only one project per
  player receives the automatic bonus.
- Below full Integrity, construction remains protected. Manual early commissioning
  at 7+ remains available and stops passive building of that Castle.
- At current maximum Integrity, the Castle activates, becomes vulnerable/operational,
  emits a `CASTLE_ACTIVATED` fact and clears the project. No other Castle is selected
  automatically. Reaching a lowered Deimos ceiling also completes the project.
- Activated damaged Castles require Repair. Existing invalid-action atomicity,
  card reservations and reconstruction eligibility remain in force.

The construction profile version changes because identical old saves/seeds must
not silently replay with new rules. Start a fresh board; old V1 construction
snapshots intentionally fail the content-policy check.

## Artillery impact presentation

`ARTILLERY_FIRED` now carries public target Castle attributes immediately before
and after that specific shot. The board initially displays the first pre-shot
state for each affected Castle. `U13ArtilleryView` emits exactly one impact signal
when its bolt crosses the flight boundary; that signal updates the existing card's
Integrity caption, tooltip and fracture artwork without rebuilding the row.
Sequential normal/War Machine shots therefore show each intermediate damage state.
Lethal damage appears on the lethal bolt's impact. Large frame deltas still emit
one impact per current shot. Skip/restart cancel the presentation tape and use the
normal authoritative final refresh. Missing projectile art falls through without
stalling presentation. Simulation damage and replay timing remain hook-based.

A small clock gate checks pre-impact, repeated explosion frames, sequential and
lethal shots, clearing and large frame deltas. The direct-board gate checks that
the actual target card starts at pre-shot Integrity and changes at impact.
